# Code review — 25 Nov 2026 (memory, security, stability)

**Branch:** `fix/review-hydras-editor-aws`. It starts from `feature/calibration-phase3-hydras` (the latest calibration
work) and merges in `feature/calibration-correction` (the IMS forecast/alerts fixes and the OS certificate store).
**How it was checked:** I read the code, built an import graph to find dead modules, ran both test suites, ran
`npm audit`, ran `cfn-lint`, and drove the app end-to-end in Chrome against PostgreSQL 16.

## Fixed

| # | Area | Finding | Fix |
|---|---|---|---|
| M1 | Memory | `get_predictions.MODEL_CACHE` was a plain dict with no size limit: one entry per station × `steps`, and `steps` can be up to 2000. It also compared `timedelta.seconds`, which wraps every 24 h, so day-old forecasts were served as fresh. | Bounded TTL/LRU cache (64 entries, 1 h) |
| M2 | Memory / DB | Two SQLAlchemy engines per process (`shared.database` and `database_production`). Each Lambda container held two DB connections, and the on-prem server opened up to 30. | `database_production` reuses the shared engine |
| M3 | Startup | `metadata.reflect()` reflected the whole schema on every cold start. | Reflects only the 4 tables it uses |
| M4 | Browser memory | CSV download blob URLs were never released. | `URL.revokeObjectURL` after the download |
| M5 | Browser CPU | The chart config logged to the console on every render and rescanned all data to count anomalies. | Debug code removed |
| S1 | DoS | `/api/analytics` passed `window_hours` straight into a SQL window frame (`ROWS n PRECEDING`) with no limit. | Limited to 1–720 h and at most 5 values; `period_days` and `lag_hours` are clamped |
| S2 | DoS | A token with an unknown `kid` forced a JWKS download from Cognito on every request (on-prem token verification). | JWKS is fetched again at most once a minute |
| S3 | Transport | The sync Lambda connected to Aurora with `sslmode=prefer`. | `require` for Aurora |
| S4 | Data exposure | The raw export of original values (with corrections) was not restricted. | `series=raw` is admin-only |
| S5 | Secrets hygiene | `frontend/Env.txt` and `.claude/settings.local.json` were committed. | Removed and git-ignored. **Rotate any key that was in Env.txt** (it is still in git history) |
| B1 | Correctness | `/api/export` was labelled "full resolution" but read through `get_data`, which caps at 5000 rows and aggregates long ranges. | Dedicated full-resolution export query |
| B2 | Correctness | Undo after a commit that removed rows did not bring those rows back (it used `UPDATE`, which never inserts). | Undo now upserts the previous rows |
| B3 | Correctness | With the editor open after a commit, a new preview was hidden behind the old "Saved" message. | The preview replaces the result |

## Cleanup

About 130 files removed or moved: ~25 AI status/report `.md` files at the root and in `docs/`, dead backend
modules (`config.py`, `security.py`, `models/`, `services/`, 7 unused `shared/*` modules, `optimizations/*.py`,
`tmp_*`, test scratch scripts, quarantined legacy tests), JSON data dumps (`corrections_*.json`,
`outliers_full.json`), per-Lambda `requirements.txt` files (replaced by one image), `docker-compose.yml` (pointed to
Dockerfiles that don't exist), `setup_aws_credentials.ps1` (long-lived keys), 13 unused frontend components and
utilities, and the Plotly dependency (unused: the dashboard uses Chart.js). The main JS bundle is 18 kB smaller and
`npm install` has 230 fewer packages. The Hebrew deployment notes moved to `docs/archive/`, and the guides moved
to `docs/guides/`.
